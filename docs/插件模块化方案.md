# 插件模块化方案（建议稿）

> 定位：为 GUI 侧边栏"🔌 插件"入口做一个**独立的插件模块**。
> 插件系统与内部工具是**两套东西**：内部工具（click/type_text/...）保持现状不动，
> 插件是往 Agent 上"加装"外部能力的扩展机制，只在创建 Agent 时合并进工具清单。

## 1. 边界划分（先说清楚什么不动）

| | 内部工具 | 插件 |
|---|---|---|
| 位置 | `agent_loop.py` / `agent_vision.py`，**保持现状** | `%LOCALAPPDATA%/DesktopAgent/plugins/` 下的用户文件 |
| 代码来源 | 随 exe 发布，随代码走 | 用户/第三方后放进来的 .py 文件 |
| 风险分级 | `core/guard.py` 现有规则 | 插件声明 `default_risk`，缺省 **medium**（fail-closed） |
| 生命周期 | 永远可用 | 可启用/停用，停用后对 LLM 完全不可见 |

依赖方向（单向，禁止反向）：

```
gui.py ──────┐
             ▼
agent_loop.py ──▶ plugin_system/ ──▶ core/（settings/paths/guard）
                    ▲
                    └── 运行时动态加载：用户插件目录里的 .py
```

`plugin_system/` **不 import** `agent_loop`、不 import `gui`，可以独立开发和测试。
它只做一件事：把用户插件目录里的文件，变成一份"可用工具清单"交给 Agent。

## 2. 目标

1. 新建 `plugin_system/` 独立包：加载、启停、错误隔离、工具清单输出，全部自包含。
2. 内部工具零改动；`agent_loop.py` 只加**一个合并点**（~20 行）。
3. GUI"🔌 插件（即将上线）"换成真面板：列表/开关/打开插件目录/重新加载。
4. 用户装插件 = 把一个 .py 文件丢进插件目录，无需改代码、无需重新打包 exe。
5. exe 打包**不受影响**——插件目录在用户数据目录，不进 PyInstaller 包。

## 3. 插件长什么样（用户视角）

一个插件 = 一个 .py 文件，放进 `%LOCALAPPDATA%/DesktopAgent/plugins/`：

```python
# plugins/天气查询.py
NAME = "天气查询"
VERSION = "1.0.0"
DESCRIPTION = "查询指定城市的天气"

def get_tools():
    return [{
        "name": "query_weather",
        "description": "查询城市天气",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string", "description": "城市名"}},
            "required": ["city"],
        },
        "run": lambda args: f"{args['city']}：晴 26℃",   # 实现
        "prompt_hint": "query_weather(city): 查询城市天气",
        "default_risk": "none",        # 无副作用；要确认的操作写 "medium"/"high"
    }]
```

要点：

- 字段与内部工具的 TOOLS_SCHEMA 结构一致，Agent 侧不需要新的分发逻辑。
- `name` 必须带前缀防撞名，加载器强制校验：插件工具名**禁止**与内部工具或其他插件重名
  （重名插件拒绝加载，报错给面板）。
- 插件要读配置（如 API key）时走 `core.settings.Settings`，约定 `plugins.<插件名>.*` 命名空间。

## 4. plugin_system/ 模块设计

```
plugin_system/
├── __init__.py        # 对外只导出 PluginManager
├── contract.py        # PluginTool 数据类 + 校验（必填字段、名字合法性、撞名）
└── manager.py         # 扫描目录、动态加载、启停、错误隔离
```

`PluginManager` 的公开接口（gui 和 agent_loop 只看这四个方法）：

```python
class PluginManager:
    def __init__(self, settings: Settings): ...      # 读 disabled 列表与插件目录路径
    def reload(self) -> None                         # 重新扫描目录（GUI"刷新"按钮）
    def list(self) -> list[PluginInfo]               # 面板展示：名称/版本/描述/状态(启用|停用|加载失败+原因)
    def enabled_tools(self) -> list[dict]            # 交给 Agent 的工具清单（schema+run+prompt_hint+risk）
```

加载规则（全部 fail-closed，坏插件不拖垮主程序）：

1. 扫描目录下 `*.py`，逐个 `importlib.util.spec_from_file_location` 加载；
2. 每个文件在隔离中执行：缺 `NAME`/`get_tools` → 记"加载失败"，继续下一个；
3. `get_tools()` 返回值逐条校验（contract.py），不合格的工具丢弃并记原因；
4. 崩溃的插件只在面板显示红色状态与错误信息，主流程不受影响；
5. 停用的插件（Settings 里的 `plugins.disabled` 名单）根本不加载，对 LLM 不可见。

## 5. agent_loop.py 的合并点（唯一的改动）

```python
class DesktopAgent:
    def __init__(self, ..., plugins: PluginManager = None):
        ...
        self._plugin_tools = plugins.enabled_tools() if plugins else []
        self.tools_schema = TOOLS_SCHEMA + [
            {"type": "function", "function": {
                "name": t["name"], "description": t["description"],
                "parameters": t["parameters"]}}
            for t in self._plugin_tools]
        self.messages = [{"role": "system",
                          "content": SYSTEM_PROMPT + self._plugin_prompt()}]

    def _plugin_prompt(self):
        if not self._plugin_tools:
            return ""
        return "\n\n已启用的扩展插件工具：\n" + "\n".join(
            f"- {t['prompt_hint']}" for t in self._plugin_tools)

    def _execute_tool(self, name, args, risk):
        plugin_tool = next((t for t in self._plugin_tools if t["name"] == name), None)
        if plugin_tool is not None:
            return str(plugin_tool["run"](args))   # 插件执行；risk 已按 default_risk 走 guard/approval
        ...  # 原有内部工具逻辑原样保留
```

`_run_loop` 里 `self.llm.chat(self.messages, TOOLS_SCHEMA)` 改传 `self.tools_schema`。
其余（重试、审计、审批）内部工具路径一行不动。

## 6. GUI 插件面板

把 `gui.py:663` 的占位 Label 换成按钮，点开一个面板（复用设置面板的样式）：

| 元素 | 行为 |
|------|------|
| 插件列表 | 名称、版本、一行描述、状态徽章（✅ 启用 / ⏸ 停用 / ❌ 加载失败+原因） |
| 每行开关 | 写 `Settings.plugins.disabled`，下次建 Agent 生效（第一版不做热插拔） |
| 📂 打开插件目录 | `os.startfile(插件目录)`，把 .py 丢进去即安装 |
| 🔄 重新加载 | `manager.reload()`，列表即时刷新 |

安装说明放面板底部一行小字："把插件 .py 文件放入上面打开的文件夹，点刷新"。

## 7. 分四步落地（每步独立可验收）

| 步骤 | 内容 | 验收 |
|------|------|------|
| **① 模块本体** | `plugin_system/`（contract + manager）+ `test_plugin_system.py`：用 tmp 目录里的样例插件测加载/撞名/坏文件/启停 | 该模块测试全绿，**不 import agent_loop 也能跑** |
| **② 合并点** | agent_loop.py 按 §5 加 `plugins` 参数与合并逻辑；guard 对插件工具按 `default_risk` 兜底 | 冒烟：塞一个示例插件，LLM 能看到并调用它 |
| **③ GUI 面板** | §6 的面板替换占位；Settings 加 `plugins.disabled` 默认值 | 面板列出/启停/刷新可用；停用后 LLM 不可见 |
| **④ 示例与文档** | 附一个 `examples/天气查询示例插件.py`；README 加"插件开发指南"小节 | 用户按文档 5 分钟做出一个能跑的插件 |

## 8. 关键设计点与坑

1. **撞名防线**：插件工具与内部工具同名会被 LLM 混淆，加载器必须拒绝重名（内部工具名
   单表硬编码在 contract.py 里做黑名单即可，不产生对 agent_loop 的 import）。
2. **fail-closed 风险**：guard.py 规则表按工具名匹配，插件工具大多不在表内。规则：插件
   工具 risk = max(插件声明值, guard 命中值)，且声明缺省一律视为 medium——防止插件把
   删文件类操作标成 none 绕过审批。
3. **prompt 顺序稳定**：`enabled_tools()` 按文件名排序输出，避免每次启动 prompt 抖动
   （LLM 对工具清单顺序敏感）。
4. **插件是任意代码**：面板和 README 明示"只安装可信来源的插件"；本期不做沙箱/签名，
   这是有意取舍，写进文档。
5. **打包零改动**：插件目录在 `%LOCALAPPDATA%`（沿用 `core/paths.data_dir()` 约定），
   PyInstaller spec 不用动；`core/paths.py` 顺手补一个 `plugins_dir()` 帮助函数。
6. **异常 Hungarian 不碰**：插件 run() 抛异常时在 `_execute_tool` 捕获，返回
   `"错误: 插件 xxx 执行失败 - ..."` 给 LLM，与内部工具的错误风格一致。

## 9. 收益小结

- 内部工具一行不动，风险为零；插件系统是纯增量模块。
- 装插件 = 丢一个 .py 文件进文件夹，无需改代码、无需重新打包。
- "🔌 插件（即将上线）"占位兑现，后续 marketplace/一键安装有了明确落点。
- `plugin_system/` 可独立测试、独立演进（未来加权限声明、插件设置页都在模块内完成）。
